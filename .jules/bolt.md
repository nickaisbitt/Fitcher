## 2024-05-06 - Replacing O(N²) array operations
**Learning:** Heavy use of `Array.shift()`, object spreading (`...obj`), and multiple `.reduce()` chained loops within `for` loops in Node.js creates significant GC thrashing and O(N²) complexity loops, forming a substantial bottleneck on performance paths like BacktestEngine execution.
**Action:** Replace `.shift()` with index pointers, `.splice()` for bulk deletion, and replace `.reduce()`/`.filter()` chaining with single pass loops.
## 2024-06-10 - Eliminate Array.prototype.reduce overhead in Node.js
**Learning:** Overuse of `Array.prototype.reduce` and chaining `.map().sort()` inside frequently called calculation methods (like generating latency stats, computing weighted signal confidence, or scanning order books for liquidity) generates unnecessary GC thrashing, creates throwaway arrays, and invokes callback function overhead repeatedly per element. Welford's online algorithm is optimal for one-pass variance calculations, avoiding dual-pass `reduce` approaches.
**Action:** Replace `reduce()` with standard `for` loops wherever arrays are large or called frequently, particularly inside core aggregation or performance-critical logic. Aggregate multiple values in a single loop instead of sequential iterations. When creating numeric arrays explicitly for statistical processing, pre-allocate `Float64Array` instead of standard arrays to avoid Object allocation and GC pauses.
