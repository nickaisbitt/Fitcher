## 2024-05-06 - Replacing O(N²) array operations
**Learning:** Heavy use of `Array.shift()`, object spreading (`...obj`), and multiple `.reduce()` chained loops within `for` loops in Node.js creates significant GC thrashing and O(N²) complexity loops, forming a substantial bottleneck on performance paths like BacktestEngine execution.
**Action:** Replace `.shift()` with index pointers, `.splice()` for bulk deletion, and replace `.reduce()`/`.filter()` chaining with single pass loops.
## 2026-05-16 - Math/Array Optimization Anti-Patterns
**Learning:** This codebase frequently calculates standard deviation/variance using chained `.reduce()` methods in hot paths like `SmartOrderRouter.js`, `strategyOptimizer.js`, and `PaperTradingEngine.js` (e.g. `returns.reduce(...) / returns.length`). This creates large GC overhead and is up to 15x slower than a manual, two-pass `for` loop. Similarly, mapping and sorting latency arrays with standard arrays is about 4x slower than passing values directly into a pre-allocated `Float64Array`.
**Action:** When calculating statistics (mean, variance) in high-throughput engines, always replace chained `reduce` calls with traditional `for` loops. When collecting and sorting numeric data streams (like latencies), strictly use TypedArrays (`Float64Array`) initialized to the known array length instead of object-heavy standard arrays.
